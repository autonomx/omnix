Assistant, tools & generalized agents

Live assistant

Chat includes voice sessions, browser/native STT paths, streaming TTS, character/Live2D identity, memory controls, message feedback, HTML/research artifacts, and live-call evaluation/diagnostics.

Governed tools

Assistant tools are projected from a canonical capability registry. Browser, workspace/code, Gmail, Calendar, Contacts, GitHub, web research, market data, Kasa, and other adapters carry explicit scope, risk, approvals, credentials, and audit metadata.

Coding/agent runtime

Semantic routing, planning, TaskGraphs, resource grants, isolated workspaces, Pi execution, acceptance, evidence coverage, final-candidate testing, independent review, durable workflows, and recovery wrap model reasoning with system authority.

Models decide how to reason and which issued tools to use. Omnix decides which capabilities exist, what workspace/candidate is authoritative, what evidence counts, which approvals apply, and whether completion gates passed.

Architecture

Browser — React / TypeScript / Vite │ shared API client + events ▼ FastAPI Web Gateway ├─ chat / assistant context ├─ RPG / replay ├─ providers + models ├─ jobs / assets / reports ├─ settings + diagnostics └─ generalized agent runtime │ ├────────────► PostgreSQL — authoritative structured persistence ├────────────► artifact / blob storage └────────────► local or remote services LLM · TTS · STT · image · Hermes · market data · integrations

Authority

Backend/domain services own persistent truth. The browser owns layout, selection, unsaved form state, playback state, and intentionally local preferences.

Shared infrastructure

Every feature reuses provider/model discovery, jobs/runs, assets/artifacts, events, settings, diagnostics, typed APIs, and the same web shell.

Realtime

SSE is preferred for job/progress/server updates. Bidirectional realtime is reserved for interactive experiences such as live voice.

Workers

Heavy models can run in separate local environments/processes. Model installation, service readiness, and in-memory residency are modeled separately.

Setup

Core development path

# PostgreSQL
docker compose -f docker-compose.postgres.yml up -d
export OMNIX_DATABASE_URL='postgresql://omnix:<password>@127.0.0.1:5432/omnix'

# Backend dependencies + DB migrations
pip install -r requirements.txt
export PYTHONPATH=src
python -m app.persistence migrate
python -m app.persistence verify

# Frontend dependencies
npm install

# Terminal 1: gateway
python -m uvicorn app.gateway.main:app --host 127.0.0.1 --port 8000

# Terminal 2: web
npm run web:dev

Open http://localhost:5173/. Vite proxies /api and /events to the gateway on port 8000.

Development model

New UI

Build inside src/apps/web/src/features, register routed modules centrally, reuse design primitives, Query, events, and the typed API client.

New long task

Create a shared job/run with semantic stages, progress, cancellation/retry behavior, resource class, and asset-backed outputs.

New provider

Implement it in the provider layer, advertise capabilities, expose health/readiness, keep credentials out of UI/source, and make feature selection capability-driven.

New tool

Register a canonical capability with effect, risk, scope, approval, network/credential/confirmation metadata and broker it through the governed runtime.

New setting

Declare scope, persistence owner, writability, effective timing, restart requirement, and a real runtime consumer.

Schema change

Add a PostgreSQL migration, test clean + upgrade paths, run persistence verification, and do not add a parallel SQLite runtime path.

The classic src/templates/src/static browser UI is retired. Compatibility backend routes may remain, but new browser behavior belongs in the shared React app.

Operations & diagnostics

Shared Jobs / Runs
Inspect module/type, queue/execution state, semantic stages, resource class, progress, logs, live event status, and cancel active work. Feature pages show filtered views of the same shared system.
Assets / Reports
Generated media and documents are indexed through shared asset/report metadata instead of feature-specific hidden output stores. Text artifact reads are guarded by type/size policy at the gateway.
Providers / Models
Inspect capabilities, status, source/family, latency/errors, discovered models, local/remote location, resource/VRAM hints, defaults, and refresh jobs.
Settings
Categories cover appearance/accessibility, AI providers, trading data, models/runtime, assistant/chat, voice/audio, storyteller/podcast, RPG, image/STT, tools/integrations, storage/operations, and diagnostics/developer settings.
Diagnostics
Use gateway/worker/provider health, event-stream state, logs, model residency, database verification, and feature-specific job errors to isolate which layer is unavailable.
