| 2026-09-27 | WP-0.5 | Durable feature executors inject their originally captured lease at the trusted proxy; LocalJobExecutor retains the claim's token. | Existing feature handlers need no database-row credential lookup, and lease takeover between the proxy check and finalization remains fenced by the database statement. |
| 2026-09-27 | WP-0.5 | Completion/failure compare expiry with `clock_timestamp()` instead of transaction-start time. | A transaction can outlive its lease. Deterministic PostgreSQL regressions expire the lease after transaction start and verify rejection without sleeps. |
| 2026-09-27 | WP-0.5 | Run the existing PostgreSQL architecture gate with both database environment variables pointing to the task-owned disposable database. | Four memory tests also construct the default settings store. | 2026-09-27 | WP-0.5 | Store the service token in a separate protected file alongside Windows provider secrets, and publish it using an atomic hard link. | Provider API-key payloads need no mutation. Concurrent launchers cannot overwrite an existing token or observe a partial file. POSIX uses the roadmap's mode-0600 secure path. Corrupt credentials fail closed. |
| 2026-09-27 | WP-0.5 | Read encrypted credentials using binary mode on Windows. | A native DPAPI test caught CRT text decoding corrupting encrypted bytes; `O_BINARY` preserves the stored ciphertext exactly. |
| 2026-09-27 | WP-0.5 | Generate credentials only in local mode and omit them from the web development child's environment. | Enterprise processes require explicit provisioning; frontend tooling has no service authority. Generation occurs at runtime launch rather than service-spec construction or read-only checks. |
| 2026-09-27 | WP-0.5 | Browser STT uses a gateway proxy for transcription, authority and WebSockets. | Browser WebSockets cannot set the service header. Explicit custom browser provider URLs remain configurable; managed STT uses `/api/stt`. |
| 2026-09-27 | WP-0.5 | Guard model services at the ASGI boundary, replacing the existing Host/Origin guard composition with an authenticated composition of the same guard. | Every non-health route, including docs and WebSocket handshakes, is protected without per-endpoint omissions. Error envelopes contain only a code and server-generated request ID. |
| 2026-09-27 | WP-0.5 | Service credentials are sent only to process-configured model targets, with redirects disabled. | Worker job input and mutable STT provider settings must not choose a recipient for the new private credential. General third-party OpenAI/TTS/LLM providers do not receive the Omnix service token. Remote/custom STT uses `OMNIX_STT_URL`. |
| 2026-09-27 | WP-0.5 | Retain the supported `websockets>=12` transport for the STT proxy and override its redirect hook. | The legacy Connect API supports the repository's current dependency floor and does not use system proxies. | 2026-09-27 | WP-0.5 | Permit unleased transitions only for owned inline chat and exact `rpg.turn.foreground_record` audit jobs with their original started submission claim. | Generic `inline_execution`/`record_only` metadata previously authorized arbitrary jobs. SQL now rejects any worker lease, requires live matching chat ownership or the exact attached RPG claim, and both worker-claim implementations exclude RPG audit records. Ownerless legacy chat remains recoverable but cannot execute. |
| 2026-09-27 | WP-0.5 | Carry foreground RPG ownership in a context-local trusted execution scope and pass its original claim into atomic turn persistence. | The turn mirror already owns the durable claim. The scope binds workspace/session/submission/job and is cleared on exit; no credential enters public request models or job metadata. Atomic persistence no longer borrows a submission token or worker lease from a row. Direct trusted persistence may create a fresh claim only when no existing claim is present. |
| 2026-09-27 | WP-0.5 | Reject foreground job types and execution-authority compatibility keys at public generic job admission. | Chat and RPG turn routes own foreground admission. A browser cannot manufacture those audit records; ordinary feature jobs still enter the leased worker queue. Existing persistence fixtures now use actual production job types and retain credentials returned by their own claims. |
