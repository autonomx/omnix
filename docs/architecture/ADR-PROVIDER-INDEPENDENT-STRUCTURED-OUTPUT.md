# ADR: Provider-independent structured output boundary

## Status

Accepted for incremental migration.

## Context

Structured LLM output is currently negotiated, parsed, retried, and validated independently by multiple features. Provider-specific response-format behavior therefore leaks into application code, malformed output can be confused with valid empty output, and loosely typed mappings can cross simulation or persistence boundaries.

## Decision

Every registered structured LLM operation must use `app.providers.structured`.

The boundary has four layers:

1. Provider transport reports preferred structured modes and returns canonical chat responses.
2. `StructuredOutputGateway` negotiates modes, decodes JSON, validates Pydantic models, applies bounded corrective retries, and returns a typed value or typed failure.
3. Features own contracts, semantic validators, and fallback policy.
4. Simulation and persistence independently accept only validated or compiled domain values.

The application invariant is:

> Every structured LLM operation either produces a validated typed value or a typed failure. Unvalidated data cannot cross structured-output, simulation, compilation, or persistence boundaries.

## Constraints

- Pydantic models are authoritative.
- Provider-facing schemas may be simplified, but Python validation is never weakened.
- Generic parsing may remove a surrounding JSON fence, select canonical tool arguments, or isolate one obvious JSON object. It must not invent fields, guess enum values, repair truncation, or delete invalid rows.
- A single absolute deadline and provider-call budget applies to each operation.
- Deterministic fallback behavior remains feature-owned.
- Valid emptiness and generation failure are distinct outcomes.
- Trusted provider diagnostics are generated by application code and are not accepted from model output.
- Raw model responses are not logged by default.

## Migration guard

New feature code must not select `response_format` by provider name, define a feature-local structured JSON extractor, or call deprecated `complete_json()` for registered structured contracts. An AST-based CI rule will become mandatory after existing callers are migrated.
